# v109 分茶铺 · 设计与实现

日期：2026-10-06。设计、前端与测试：Claude；场景原画：本机 Codex CLI（内置 image generation）。状态：已实装。

## 1. 从 v108 接过来

v108 把光借进了三间暗屋，屋里的人终于读完了报，想喝一杯茶。可死人只要正好那么多：回声档案室的客人只要一口，血管维修井的要四口，忏悔称量室的要七口——“一口一件事，多一口就是撒谎”。

> 分茶铺很小，炉子上坐着一把铁壶。柜台上三只托盘，三张茶单，三只空杯，一只比一只大。

## 2. 新交互：量杯倒茶

- 分茶台左边一把铁壶（无限）、右边一只水盆，中间三只没有刻度的量器（原生按钮，`aria-pressed` 表示端起，`aria-label` 读出容量与现有口数）。量器高度按容量缩放，茶的高度按口数实时变化。
- 点一只端起来；再点另一只就倒进去，倒到那只满或这只空为止（`etPourStep` 纯函数）；端着时可以“从壶里灌满”或“倒回水盆”；点同一只放下。
- 哪一只里正好是客人要的口数，那只量器发亮，才能“奉茶”。口数只放在内存里：换茶具、换客人、点“全部倒掉重来”都会倒空，茶在途时量器锁定。
- `etMinSteps` 用 BFS 求最少步数；测试对 9 种组合逐一确认目标量不能直接从壶里灌出、最少要 3–7 步，并用测试自己的规划器按真实点击（端起 / 灌满 / 倒空 / 倒进）量出来。

## 3. 三位客人 × 三套茶具

| order | 客人 | 口数 | 送回 | 茶童 |
| --- | --- | ---: | --- | --- |
| `echo-order` | 回声档案室的一口 | 1 | `echo` | 档案室茶童 |
| `vein-order` | 血管维修井的四口 | 4 | `vein` | 维修井茶童 |
| `confession-order` | 忏悔称量室的七口 | 7 | `confession` | 称量室茶童 |

| method | 茶具 | 容量 | 最少步数（1 / 4 / 7 口） |
| --- | --- | --- | --- |
| `clay` | 粗陶 | 3 / 5 / 8 | 4 / 6 / 5 |
| `copper` | 铜壶 | 2 / 5 / 11 | 4 / 3 / 4 |
| `porcelain` | 白瓷 | 3 / 6 / 11 | 4 / 6 / 7 |

收集键 `order:method`，3×3 = 9。奉茶后茶送到那个房间，出现“奉茶签收”，点茶童回分茶铺；该房间多一段随最近那套茶具变化的记忆。

## 5. 数据与边界

- 独立键 `goddead_v109_exact_tea`，version 109，十一字段：version、visited{house, table, court}、draft{order, method}、pours、courtOutcomes、pourRuns、courtRuns、latestMethodByOrder、lastOutcome、activeServer{pour}、pending。
- pending 七类（entry / order / serve / abandon / server-return / court-entry / verdict），按 kind 与当前状态重建期望对象，逐字段一致才接受。
- 解锁：v108 开庭条件满足且三项裁定全收集；v108 有在途的光或未签收的点灯人时入口禁用。
- 前缀 `et-`；模块内只有一个事件绑定点（真实点击助手）；存档内容只以 textContent 渲染；`exactTeaBridgeAllows` 接入治理守卫、画廊守卫，以及 v29 分支守卫（回声档案室 / 血管维修井 / 忏悔称量室未探索时也能收茶）。
