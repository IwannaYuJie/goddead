# v110 扫尘司 · 设计与实现

日期：2026-10-06。设计、前端与测试：Claude；场景原画：本机 Codex CLI（内置 image generation）。状态：已实装。

## 1. 从 v109 接过来

v109 的茶喝完了，三间旧屋要关门过夜。代神席前落着替神坐着的人磨下来的金灰，焚献炉周围是还带火星的炉灰，值夜室的地上是灯烟落下的黑灰。扫尘司派扫帚去扫。

> 扫尘司是一间窄窄的库房，墙上挂满扫帚和簸箕。长桌上三只铜簸箕，各盛着一小堆不同的灰。

## 2. 新交互：一笔扫完

- 那间屋的地是俯视的 5×5 石砖（原画砖缝按像素实测对齐），落满了灰；有几块被挪不动的家具占着。
- 25 块砖都是原生按钮。扫帚从选定的门口起，每次只能扫挨着扫帚（上下左右）的一块落灰地砖；扫过的不能再踩、家具不能扫；点扫帚所在的砖退回一步，“回到门口重扫”清空路线。
- 扫过的砖露出深色石面，扫帚停的那块发亮，挨着扫帚的落灰砖有描边提示；路线用 SVG 折线实时画出，每块都扫到时整条路线变金，状态行报“22 块地砖都扫过了，一块也没重踩”。四面都走不通时状态行会提示退回。
- 只有扫遍全屋（`swComplete`：从门口起、一步一格、每块落灰砖正好一次）才能“收簸箕”。路线只放在内存里：换门、换屋都会让地上重新落灰，扫完在途时扫帚锁定。
- `swCountPaths` 深搜计数；测试确认 9 种组合各有 2–10 种扫法，并用测试自己的深搜找出一条路线让模块验收。

## 5. 数据与边界

- 独立键 `goddead_v110_last_sweep`，version 110，十一字段：version、visited{office, floor, court}、draft{room, method}、sweeps、courtOutcomes、sweepRuns、courtRuns、latestMethodByRoom、lastOutcome、activeSweeper{sweep}、pending。
- pending 七类（entry / room / finish / abandon / sweeper-return / court-entry / verdict），按 kind 与当前状态重建期望对象，逐字段一致才接受。
- 解锁：v109 开庭条件满足且三项裁定全收集；v109 有在途的茶或未签收的茶童时入口禁用。
- 前缀 `sw-`；模块内只有一个事件绑定点（真实点击助手）；存档内容只以 textContent 渲染；`lastSweepBridgeAllows` 接入治理守卫与画廊守卫。签收处代神席、焚献炉、值夜室的主线守卫在终局后章节阶段恒满足，无需额外桥接。
