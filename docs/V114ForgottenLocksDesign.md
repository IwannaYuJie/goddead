## 1. 从 v113 接过来

v113 把供都撤了，三间旧屋要锁门过夜。可值夜室的门、遗物科的柜子、投递所的信箱，锁上都还是神设的老密码，谁也不记得。锁匠说只能一次次试，锁会告诉你差多少。

> 锁匠铺墙上挂着几百把旧钥匙。柜台上三把锁，转轮上刻着字，谁也不记得神设的是哪几个。

## 2. 新交互：试锁（猜密码）

- 试锁台正中的皮垫上排着 3 或 4 个转轮（原生按钮，点一下转到下一个字，`aria-label` 读出当前的字），字从日、月、星、灯、火里取，可以重复。
- 拨好了点“试一试”：锁会“咔”几声（字和位置都对）、“嗒”几声（字对但位置不对）（`lkScore` 纯函数，重复字不重复计数）。试过的记录列在下面，最近的在上，最多显示 8 条。
- 只有最后一次“试一试”就是这组字、并且咔满了（`lkSolvedNow`），才能“换锁芯”；试开后再拨动转轮会重新锁上。转轮与记录只放在内存里：换锁芯、换锁、“从头试”都会清空，换芯在途时转轮锁定。
- 测试用“每次都猜一个与所有反馈一致的密码”的策略验证：9 组密码都能在 7 次内试出来（实际 4–6 次）。

## 5. 数据与边界

- 独立键 `goddead_v114_forgotten_locks`，version 114，十一字段：version、visited{shop, bench, court}、draft{lock, method}、unlocks、courtOutcomes、unlockRuns、courtRuns、latestMethodByLock、lastOutcome、activeKeyholder{unlock}、pending。
- pending 七类（entry / lock / finish / abandon / keyholder-return / court-entry / verdict），按 kind 与当前状态重建期望对象，逐字段一致才接受。
- 解锁：v113 开庭条件满足且三项裁定全收集；v113 有在途的供盘或未签收的撤供人时入口禁用。
- 前缀 `lk-`；模块内只有一个事件绑定点（真实点击助手）；存档内容只以 textContent 渲染；`forgottenLocksBridgeAllows` 接入治理守卫（神圣遗物科、痕迹室）与画廊守卫。

## 6. 美术

三张 1536×1024 由本机 Codex CLI 生成：挂满旧钥匙的锁匠铺柜台上三把带转轮的老锁（铁门锁板 / 铜柜挂锁 / 青铜信箱锁）、正中空着一块深色皮垫的锁匠工作台、圆厅里的锁匠听证会（挂满钥匙的铁环 / 打开的旧挂锁 / 散落的钥匙）。提示词与哈希见 `docs/V114ImagePrompts.md`。
