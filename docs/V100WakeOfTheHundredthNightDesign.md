日期：2026-09-25。设计、前端与测试：Claude；场景原画：本机 Codex（内置 image generation）。状态：已实装。

## 1. 从 v99 接过来

v99 让路走到了尽头。神死后的第一百夜，死者为神守灵：灵堂里点着一百盏纸灯，三张供桌上反扣着牌。

> 灵堂里点着一百盏纸灯。三张供桌上反扣着牌，每张牌背都有一滴红蜡。

第一百版用一个“守灵”的章节收一收尾：三副供牌取自焚献炉、余响交换台、无主投递所，都是玩家早就熟悉的房间。

## 2. 新交互：翻牌配对

- 翻牌供桌上是 16 个原生按钮牌位，按更次发 8 / 12 / 16 张，多余的牌位隐藏。牌背红漆加蜡点，翻开是羊皮纸上的一个字，带 3D 翻转。
- 一次翻两张：一样的就配上、描金留着；不一样的停 1.2 秒后扣回，或者翻第三张时先扣回。反扣着的牌不在 DOM 里留字，读屏只读“反扣着”。
- 状态行实时显示翻了几次、配上几对、翻错几次。“全部扣回”重来（摆法不变），换更次会重新发牌。全部配齐才能上香。
- 摆法由“供牌 + 更次”确定性洗出（FNV 散列 + mulberry32），同一局每次一样，测试可以重现。
- 翻开的牌只放在内存里，不写存档；香在途时供桌锁定。

## 5. 数据与边界

- 独立键 `goddead_v100_hundredth_wake`，version 100，十一字段：version、visited、draft{deck, method}、rites、courtOutcomes、riteRuns、courtRuns、latestMethodByDeck、lastOutcome、activeMourner{rite}、pending。记录名用 `rites`，避开已有的 `offering` 场景名。
- pending 七类（entry / deck / incense / abandon / mourner-return / court-entry / verdict），按 kind 与当前状态重建期望对象，逐字段一致才接受。
- 解锁：v99 开庭条件满足且三项裁定全收集，经 `store.memo` 缓存；v99 有在途记录时入口禁用。
- 前缀 `wk-`；模块内只有一个事件绑定点（真实点击助手）；存档内容只以 textContent 渲染；`hundredthWakeBridgeAllows` 接入治理守卫与画廊守卫。

## 6. 美术

三张 1536×1024 由本机 Codex CLI 生成：纸灯下三张反扣着供牌的黑漆供桌（香炉 / 交换台插板 / 一摞信）、俯视的黑漆供桌（中间整片留空给牌）、一圈白蜡烛围着空椅子、天刚发灰的听证厅（铜公鸡 / 反扣的供牌 / 没点的香）。提示词与哈希见 `docs/V100ImagePrompts.md`。
