# v122 灵车场：车位记忆与退回一挪

## 目标

挪车中途刷新后，继续原来的车位与步数；加一个原生「退回一挪」按钮。保留 v117 的九个固定车阵、最短步数、放行 / 签收 / 听证和 v118 解锁。场景仍为 280，静态缓存升到 `v=122`，沿用已有三张灵车场原画。

## 草稿合同

继续使用 `goddead_v117_hearse_yard`、version 117 和原十一项顶层字段，仅扩展 draft：`hearse`、`method`、`positions`、`moves`、`baseMoves`、`undo`。positions 按固定车序只存每辆车沿自身轴的起点；方向、长度、固定行 / 列由原车阵重建。

- 每次合法挪动保存新位置、步数和前一位置快照；选车、取消选中、非法挪动不写档。选中标记为临时界面状态。
- undo 保留最近 64 次合法挪动的前一位置，刷新可继续撤回；挪动次数不受撤回容量限制。每次撤回减一步，撤回后再挪会建立新的分支。
- 数组必须完整，位置为界内整数，每辆车长度 / 方向固定，车身互不重叠。所有撤回快照同样校验，相邻快照到当前局面只能改变一辆车，并完整通过途中碰撞检查。
- moves 与 baseMoves 均为非负安全整数，须满足 `moves = baseMoves + undo.length`，历史最多 64 项。baseMoves 记录容量截断后检查点之前的步数，撤回不会改变它；未截断的历史（baseMoves 为 0）必须从初阵开始。容量截断或撤回到容量边界后，最早合法局面作为检查点；0 步必须是初阵。序列须从该检查点连续重放到当前车位。
- 旧版只有车 / 时辰的草稿读为对应初阵、0 步、空撤回；任何坏的新增草稿字段也安全回到对应初阵，不删除既有放行 / 裁定 / 签收记录。旧七种严格 pending 的合同继续兼容，旧版已发出的车可冷恢复签收；新发车仍须当前棋盘到门。

## 操作与生命周期

相同车 / 时辰再次进入或切换房间保留草稿；换车、换时辰、「车都推回原位」开始新的 0 步局面。原「等院子空一点再来」仍是放弃本局、返回门房；文案标明会推回原位。放行后锁定格子、时辰、撤回和重置；到达旧房间时只结算一次并清空本局，赶车人签收后回门房。

三张灵车场页面局部恢复纵向滚动，修复旧 `.scene-branch { overflow: hidden }` 导致普通滚轮够不到下方按钮的问题。棋盘旁提示已挪次数和车位已记下；说明刷新保存与最近 64 次撤回。空历史时撤回按钮禁用。鼠标 / 触控与原生 Enter / Space 走同一 trusted-click 助手；遗忘沿用本章清理。

## 验收计划

独立占格 / 扫掠模型验证九阵原最短数，逐步冷恢复、撤回 / 重挪、重置与切换；验证超过 64 次仍可继续、撤回边界、坏位置 / 缺项 / 碰撞 / 穿车历史、旧档与旧在途迁移、重复抵达和上游原字节保持。跑全站与旧章测试。Chrome 桌面和 375px 手机用原生点击 / 键盘完成中途刷新、撤回、合法发车与冷签收，保存截图与原浏览器存档恢复证据。推送后核对当前提交 Pages 状态、公开资源 SHA 和首页。

## 本地验收结果

30,550 条站点断言和旧章 65/65 通过；独立模型保住九个最短解，81 次逐步冷恢复 / 撤回重挪、45 种首步与 130 步检查点边界通过。Chrome 默认 1470×779 / 手机 375×844，完成三车三时辰 4 / 8 / 14 步、三处签收、三项裁定及渡河入口；刷新、撤回、同局重入、坏草稿和发车瞬间冷恢复通过。35 上游 raw 未改，原 21 项浏览器存档恢复，新增 error / warn 为空。详见 [v122-browser-qa.md](../design-qa-evidence/v122-browser-qa.md)。
