# v125 调墨房纯规则模块

## 目标与范围

承接 v124 持续队列，先拆一个已验收工坊的纯规则。v107 的颜色 / 色差 / CSS 色值、默认与规范存档、开庭覆盖、七类 pending 构造与验证只读参数，不涉及页面或存储；将这组函数完整迁至独立 `ink-rules.js`，主脚本保留章节配置、故事、美术、解锁 / 存取、滑条内存、真实输入、抵达 / 取消 / 重播、处理员、原 guard 和初始化。

不是改色彩公式或谜题难度的一版：343 个 0–6 份组合的原 RGB / 色差 / 三档通过判定、三处样色配方、9 条收集、3 项听证、原十一字段 version 107 / 原键与 pending 七类逐字输出均保留。280 场景、4501 静态 ID 和原 278 目录入口保持；四个依赖缓存 v125，沿用 v107 三张原画。

## 模块合同

- `globalThis.GoddeadInkRules.create(config)` 接收主脚本原章节常量与表，返回该配置下的纯规则 API；不访问 DOM / window / storage / timers / Audio / routes，没有脚本外依赖。命名空间及 API 冻结，数据输入不改写，返回新的颜色和存档对象。
- 函数保持原名 / 参数 / 调用含义；配置仍在主脚本一次声明，避免两份难度 / 故事表。`mxDelay` 的 reduced 语义、玩家事件及章节 IO 留在主脚本。
- HTML 原阻塞脚本顺序：directory → ink-rules → script，均在 body 末尾。规则在主脚本创建章节 API 前已注册；不增加 DOMContentLoaded / 全局输入监听器，不引入第二份规则 fallback。
- 原站点 v107 集成测试使用真实模块后保留全部原动作 / 归一化 / 343 组合断言；执行多章源的 VM harness 先加载同一规则文件。新测试可独立于 7 万行主脚本执行。

## 验收方法

改代码前从当前已发布 v124 源留存纯函数原文与版本 SHA，生成 343 配色和原存档 / pending 的回归快照。新测试同时用独立配色推导、边界 / 三配方 / 三精度、配置隔离 / 纯函数输入不改写、新默认对象 / 归一化幂等与七类 pending 去一字段 / 多一字段 / 改值检查，避免仅验证文件存在。

差异审计逐纯函数比较迁移前后的函数体，证明原游戏动作 / guard / sync / 到访 / 初始化 / 存档键不变。规则模块单独语法 / 测试，全站及 65 项旧章，ID / hash / 依赖 / 敏感标记继续检查。真实 Chrome 桌面 / 375px 以完成 v106 的实际存档，从指引进入调墨房，方向键和鼠标滑条（窄屏为 Chrome 视口模拟）混三配方，色差 / 三档、洗碟、换精度、未匹配禁倒、旧房间签收、三裁定 / 借光入口、刷新 / 在途 / 锁定回退 / 目录焦点；原 21 项本地状态精确恢复。
