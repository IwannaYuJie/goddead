# v94 回敲邮局 · 设计与实现

日期：2026-09-24。设计、前端与测试：Claude；场景原画：本机 Codex（内置 image generation）。状态：已实装。

## 1. 从 v93 接过来

v93 在黑暗里找到了“第一下之前的敲门”。认领之后，它开始回信：每一下曾经落在门上的敲门，都被邮寄回来，要求回话。

> 回敲邮局的铃响了三下。柜台上摆着三封没有字、只有孔的信。

这一章回到整个游戏的第一个动作——敲门三下。

## 2. 新交互：节奏回敲

- 叩门间里，图上的铜门环就是一个原生按钮（空格键也能连续敲）。敲击时刻只放在内存里，不写存档。
- 判定只看节奏的相对比例：把所有间隔之和按应敲节拍均分成“单位”，每段间隔须落在应有拍数 × 单位的 0.68–1.38 倍内；每段至少 90ms、不超过 2.5s（超过即从头算）。快慢不限，只要比例对。
- 敲错会提示“节奏不对”，并可点“听一遍示范”：进度点和轻响按正确节奏放一遍，不计任何进度。
- 进度点叠在叩门间画面下部三分之一，长间隔处多留一段空，一边敲一边看得见。

## 3. 三封信 × 三种回敲

| sender | 标题 | 节奏（信上的孔） | 签收处 | 邮差 |
| --- | --- | --- | --- | --- |
| `the-door` | 门寄来的回敲 | 咚 ·咚 ·咚 | `threshold` | 门槛邮差 |
| `the-acting-seat` | 代神席寄来的回敲 | 咚 ——咚 ·咚 | `acting` | 代神席邮差 |
| `you-before-you-came` | 来之前的你寄来的回敲 | 咚 ·咚 ——咚 ·咚 | `remembrance` | 痕迹邮差 |

| mode | 方式 | 应敲的节奏 |
| --- | --- | --- |
| `echo` | 原样回敲 | 与信上相同 |
| `reverse` | 倒着回敲 | 间隔倒序 |
| `one-more` | 多敲一下 | 原样敲完再多一下 |

收集键 `sender:mode`，3×3 = 9。敲对后回信寄到寄信人所在的旧场景，出现“回信签收”（写明节奏与一句结果），点邮差回邮局；该旧场景多一段随最近回敲方式变化的记忆。换一封信把方式重置为原样；同一封信保留。

## 4. 仲裁

条件：三封信都回过、三种方式都用过。最短三次。

| action | 裁定 | 抵达 |
| --- | --- | --- |
| `let-every-door-knock-first` | 让门先敲 | `threshold` |
| `keep-a-metronome-for-the-dead` | 给死者一台节拍器 | `remembrance` |
| `let-silence-count-as-a-reply` | 沉默也算回信 | `unending-gallery` |

## 5. 数据与边界

- 独立键 `goddead_v94_returned_knocks`，version 94，十一字段：version、visited、draft{sender, mode}、replies、courtOutcomes、replyRuns、courtRuns、latestModeBySender、lastOutcome、activeCourier{reply}、pending。
- pending 七类（entry / sender / reply / abandon / courier-return / court-entry / verdict），按 kind 与当前状态重建期望对象，逐字段一致才接受。
- 解锁：v93 开庭条件满足且三项裁定全收集，经 `store.memo` 缓存；v93 有在途记录时入口禁用。
- 前缀 `rk-`；所有控件只接受真实点击；存档内容只以 textContent 渲染；代神席到达本身不会触发它原有的自动转场。

## 6. 美术

三张 1536×1024 由本机 Codex CLI 生成：邮局柜台上三封打孔信（孔距就是三段节奏）、木亭里的黑门与铜门环、穹顶吊着巨大门环的仲裁庭（桌上小门 / 节拍器 / 空白信）。源图在 `design-references/source-v94-*.png`，WebP 在 `assets/v94-*.webp`，提示词与哈希见 `docs/V94ImagePrompts.md`。
