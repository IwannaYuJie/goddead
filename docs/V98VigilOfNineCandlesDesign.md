# v98 守夜烛台 · 设计与实现

日期：2026-09-24。设计、前端与测试：Claude；场景原画：本机 Codex（内置 image generation）。状态：已实装。

## 1. 从 v97 接过来

v97 的法庭“把秤留给了神”。秤留下了，神没回来，死者开始替神守夜。三处旧房间各送来一架 3×3 的铁烛台，亮着的那几支记着它们各自那一夜。

> 守夜厅里很静，只有烛芯在响。石台上三架铁烛台，各亮着几支。

签收处是神圣遗物科、神名注销科和代神席。

## 2. 新交互：熄灯谜题

- 守夜台上九支蜡烛是九个原生按钮，按原画逐支定位（烛芯上方到烛身中段，互不重叠），亮着的蜡烛画出火苗和光晕，`aria-pressed` 表示亮 / 灭。
- 点一支蜡烛，它和上下左右挨着的几支一起翻转（亮的灭、灭的亮）。面板里有一张 3×3 的小图标出目标图案。
- 按钮：封灯（图案对上才送出）、问守夜人（高亮下一支该点的蜡烛并说还要几次，不改任何进度）、复位（回到送来时的样子）、放回石台。
- 亮灯状态只放在内存里：换守法时保持原样，换一架烛台时回到那架送来时的图案，守夜签在途时锁定。
- `vcPress` 与 `vcSolve`（枚举 512 种点法取最少）是纯函数；测试逐一验证 9 种组合都有解、解确实可行。

## 3. 三架烛台 × 三种守法

| stand | 名称 | 送来时亮着 | 送回 | 守夜人 |
| --- | --- | --- | --- | --- |
| `reliquary-stand` | 神圣遗物科的烛台 | 斜对的两个角（0、8） | `reliquary` | 遗物守夜人 |
| `cancellation-stand` | 神名注销科的烛台 | 四个角 | `cancellation` | 注销守夜人 |
| `acting-stand` | 代神席的烛台 | 正中一支 | `acting` | 代神守夜人 |

| method | 守法 | 目标图案 |
| --- | --- | --- |
| `snuff` | 全部熄灭 | 九支全灭 |
| `cross` | 点成十字 | 中间一横一竖 |
| `ring` | 点成一圈 | 外圈八支亮、正中灭 |

收集键 `stand:method`，3×3 = 9。封灯后守夜签送回那个房间，出现“守夜签签收”（送来时的图案 → 守成什么），点守夜人回守夜厅；该房间多一段随最近守法变化的记忆。

原计划遗物科的烛台是一整条对角线；Codex 的成图只点亮了对角两端，数据改为跟图一致（0、8），谜题同样有解。

## 5. 数据与边界

- 独立键 `goddead_v98_vigil_candles`，version 98，十一字段：version、visited、draft{stand, method}、vigils、courtOutcomes、vigilRuns、courtRuns、latestMethodByStand、lastOutcome、activeKeeper{vigil}、pending。
- pending 七类（entry / stand / seal / abandon / keeper-return / court-entry / verdict），按 kind 与当前状态重建期望对象，逐字段一致才接受。
- 解锁：v97 开庭条件满足且三项裁定全收集，经 `store.memo` 缓存；v97 有在途记录时入口禁用。
- 前缀 `vc-`；模块内只有一个事件绑定点（真实点击助手）；存档内容只以 textContent 渲染；`vigilCandlesBridgeAllows` 接入治理守卫（神圣遗物科、痕迹室）与画廊守卫。
