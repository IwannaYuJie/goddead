# Goddead v38 设计：门外代审窗 / THE PROXY ADMISSION WINDOW

## 目标

v38 把下一轮内容明确拉回首页与访客守则，不在 v37 之后继续加长深层链条。

- 在首页门板上增加一个干净存档即可发现的第四热点，让玩家不敲三次门也能进入新区域。
- 将守则「其八」从固定去走廊改成第二入口；原文与反馈逐字保留。
- 新增 `#proxy-admission`：玩家替门后的机构审查三名夜访者，可自由问讯，再直接决定「准许入内 / 留在门外」。
- 每次判断立刻记账并自动切到下一名访客；第三次判断自动结算并分流到四个既有前段区域。
- 正确审查积累「在场证」，误放回声或误拒在场者分别形成不同的门债，因此同样的正确数也可能走向不同分支。
- 没有确认页、底部继续按钮、新结局或主线硬门槛。

## 当前玩法参考与原创转译

只参考交互结构，不复制角色、题材、美术、台词或具体谜题。

1. `No, I'm not a Human`
   - 官方 Steam 页面把「敲门者是否应该被允许进入」与观察征兆、问讯访客、承担后果绑定。
   - https://store.steampowered.com/app/3180070/No_Im_not_a_Human/
   - 转译：Goddead 的玩家不是保护屋内的人，而是在门外替门本身筛选谁还有资格被称为「在场」。
2. `Home Safety Hotline`
   - 官方 Steam 页面强调查阅征兆、根据来电描述判断异常，并为错误判断负责。
   - https://store.steampowered.com/app/2357910/Home_Safety_Hotline/
   - 转译：三类问讯不是答案按钮，而是玩家主动索取的证词；真正改变路线的是随后的放行 / 拒绝判断。
3. `Anomaly Watcher`
   - 官方 Steam 页面把记忆细节、报告异常与表现决定结局结果结合。
   - https://store.steampowered.com/app/4766570/Anomaly_Watcher/
   - 转译：访客的名字、影子、敲门次数会互相作证或冲突；结算只落回既有前段区域，不新增结局。

本轮原创恐怖点：

- 玩家站在门外，却被门后的机构临时任命为门卫。
- 每位访客都声称自己还活着；真正的区别是他们的影子、名字和敲门声是否发生在本人之前。
- 放行回声不是把它送进门，而是让它提前进入玩家的下一段路线。
- 误拒仍在场的人会让窥孔开始怀疑玩家；误放已经只剩回声的人会让回返夹道多出一双脚印。
- 三人全部核验正确时，守则才承认玩家是「访客」而不是「下一位被审查者」。

## 两个入口

### 1. 首页门板第四热点

沿用首页现有门图，不替换三次敲门的主目标。

- 按钮 ID：`hotspot-proxy-admission`
- 可访问名称：`拉开门板下方的代审问讯窗`
- 短标签：`代审`
- 位置：门板下方偏中，避开日蚀、左墙符号、右侧回来痕迹；覆盖范围只占门按钮的一小部分。
- mark：`openedProxyWindow`
- entry：`threshold`
- 反馈：`门缝从里面拉开。值班员把你的影子登记成了代理人。`
- 自动去：`#proxy-admission`

与现有门外三热点共用门外首选锁：

- 第一个被接受的热点决定去向，后续热点和敲门忽略。
- 第三次敲门一旦接受并准备去守则，代审热点不能抢走转场。
- 代审热点一旦接受，随后敲门不能把玩家拉回守则。
- 干净存档立即可见、可 Tab、Enter、Space 激活；不要求先敲一次门。

### 2. 守则其八

守则第八条原文逐字保持：

`离开时，请确认你没有被记住。确认有效。确认无效。你会被记住。`

原有删除线、强调样式与反馈逐字保持。

- 将规则 8 加入既有 `RULE_DETOUR`，目的地改为 `#proxy-admission`。
- entry：`protocol`
- mark：`answeredProtocolEight`
- 与其余守则共用既有首选锁；「玖」异常优先级保持不变。
- 其一、其五仍走主线走廊；其二、三、四、六、七及其既有目的地全部保持。

## 门外代审窗的完整一轮

### 代审簿

场景顶部显示：

- 已审：`0/3`、`1/3`、`2/3`、`3/3`
- 在场证：0–6
- 门债：0–2
- 已问：本轮已展开的问讯数量
- 最佳核验：历史最高在场证

### 访客轮换

每轮固定三名，不使用裸随机。以 `entry + cycle` 经过白名单轮换，四轮循环：

| 轮次 | 第一位 | 第二位 | 第三位 |
| --- | --- | --- | --- |
| 0 | nurse | postman | umbrella |
| 1 | postman | widow | nurse |
| 2 | umbrella | widow | postman |
| 3 | widow | nurse | umbrella |

重载保留本轮顺序、当前访客、问讯展开状态和已完成判断；不得重新抽取。

### 单名访客的交互

每次只显示当前一名访客的大图、称谓、第一句陈述、三项问讯和两个判断按钮。所有核心控件必须在 1440×800 与 390×844 的首屏可达。

三项问讯：

1. `报上登记名`
2. `让影子先回答`
3. `请按规定敲门`

- 三项都是原生按钮。
- 点击只展开该访客对应证词、记录 questioned，不切场景、不加减分。
- 已问项保持 `aria-pressed=true`；重复询问只重播短声音，不重复累计。
- 玩家可以问零到三项，然后直接判断。

两个判断：

1. `准许入内`
2. `留在门外`

- 第一次被接受的判断锁住当前访客的全部问讯与判断按钮。
- 立即显示逐字反馈，约 0.9–1.2 秒后自动换下一人。
- 第三人判断后自动结算并换场；没有「下一位」「确认」「继续」按钮。
- reduced-motion 仍显示完整反馈，但节拍缩短至约 0.3 秒。

## 计分与四档自动分流

每名访客：

- 正确判断：在场证 `+2`
- 错误判断：门债 `+1`
- 错误放行回声：记 `admittedEcho`
- 错误拒绝在场者：记 `rejectedPresent`

第三名判断完成后结算一次：

| 条件 | outcome | 反馈 | 自动去向 |
| --- | --- | --- | --- |
| 在场证 6 / 门债 0 | `verified` | `三份证词互相承认。守则同意把你登记为访客。` | `#protocol` |
| 在场证 4 / 门债 1，且误拒在场者 | `paranoid` | `你把仍在场的人挡在门外。倒置窥孔要求先核对门卫。` | `#peephole-chamber` |
| 在场证 4 / 门债 1，且误放回声 | `contaminated` | `你放行的那道回声已经从里面敲门。回返夹道负责把它送回来。` | `#return-passage` |
| 在场证 0–2 / 门债 2–3 | `unnamed` | `门债盖过了全部在场证。失号龛收走了代审簿上的名字。` | `#glyph-niche` |

同一人不可能同时形成两种错误，因此门债为 1 时两条中档路线唯一可判定。

四档必须能通过真实 UI 正常抵达，不能只靠 localStorage 种子。

## 新 cycle、直达与状态

独立键：`goddead_v38_proxy_admission`

建议字段：

- `visited`
- `entry`：`threshold | protocol | direct`
- `cycle`
- `roster`：本轮三个合法访客 ID
- `index`
- `decisions`：每名访客仅一个合法 `admit | refuse`
- `questioned`：按访客保存三个问讯 ID 的去重白名单
- `proof`
- `doorDebt`
- `admittedEcho`
- `rejectedPresent`
- `settled`
- `outcome`
- `bestProof`
- `totalJudgments`
- `marks`

要求：

- 坏 JSON、错误类型、非法 roster / decision / question / mark 安全回退。
- `proof`、`doorDebt`、两类错误标记与 outcome 必须从合法 decisions 重算，不信任存档里的伪造数字。
- index 与 settled 必须由合法 decisions 数量规范化；少于三次决策的 settled=true 必须修回未结算。
- 每名访客判断只写一次；快速连点、Enter / Space 重复事件只认第一次。
- 反馈期间离场清除 timer；判断已经持久化，重进恢复到下一位或结算态，不幽灵跳转。
- 直接 hash 进入只记 visited，并开启 / 恢复一个正常 cycle，不自动问讯或判断。
- 已结算状态重进时开启下一个确定性 cycle；历史 bestProof / totalJudgments 保留。
- 不读取、不覆盖 v28–v37 或主线 progress。

- 静音、reduced-motion、标题聚焦、滚动归顶、scene veil 与 AutoAdvance 生命周期沿用现有契约。
