# v124 在途交接优先指引

## 问题与目标

v66–v90 的下一步会跳过下一章已解锁的旧章；v91–v117 多个工坊在覆盖和三裁定齐全时直接递交下章，先前加入的 active 签收提示随 return 丢掉。玩家重做已完成章节后，回执仍在旧房间，下一步却指向别处；现有入口还常因事务在途而禁用。

在原治理终局门槛之后、现有覆盖 / 裁定判定之前增加只读待办检查，按章节顺序检查 v63–v121 的合法 pending 与 v64 / v66–v118 的活动交接（v63 activeEnding 是正在选择的结局，不能误作待签收）。尚未解锁章继续忽略；干净档继续原指引。280 场景、原目录、全部存档键和章节归一化 / 签收 / 路由合同保持，缓存 v124。沿用已有图与指引卡，不新增美术。

## 行为合同

- 使用各章实际 getter 和 unlock 判定，不从 raw 存档推断活跃事务，也不按记录数或裁定数把合法交接视为完成；按章节顺序选第一份待办，同章 pending 优先于 active。
- pending 显示正在交接的章节及原目标房间；原生链接沿已有 hash 路由继续到合法 target，抵达结算 / 重播仍由原章负责，不自动按处理员或写 pending。
- active 显示仍在等待的房间和原交接按钮文字；从各章原签收控件的所属 scene / 隐藏容器读取实际落点，v64 的邮戳与 v70–v81 当前场景限定处理员沿原 activeEcho.target / 原 SCENE_FOR 或 residue 表读落点。不克隆处理员，不显示其他章节的控件。
- 新「前往…签收 / 继续」原生链接位于下一步卡；原「找到入口」仍只滚动 / 聚焦、不替玩家点击。忙态暂不展示普通章节入口；正常态隐藏并清空新链接，清除 stale href / 文案。
- 目标须属于原 scene 表；若活动状态存在但控件尚未呈现，仍展示待交接提示，不猜落点、不递进下章。动态文字用 textContent。
- 不改章节单独的三轴 / 谜题提示，不更改 getter、游戏动作、guard、初始化顺序或原 v123 目录；无新增存储写入、无第二套路由。已集齐裁定仍在途中、缺项尚多仍等待、跨章同时待办、待办结束后恢复下一章均覆盖。

## 验收

独立状态优先级与全注册表 / 原签收控件场景映射检查；完成解锁边界下 59 章实际 getter 的坏事务归一化、十四工坊合法 active 与完成态对照；真实 pending / active 生命周期由代表性原生路线验收，原始存储读前后一致。旧全站 / 65 项旧章测试、语法、ID / hash / 引用 / 敏感标记及缓存继续检查。

Chrome 桌面 / 375px：旧模板、手作、早餐 / 分茶 / 灵车代表 active 和在途；新链接精确到旧房间，原处理员鼠标 / Enter / Space 签收后指引继续；刷新保持、无效 / 锁定落点回退、同时存在上游交接优先和键盘焦点。原 21 项本地状态备份 / 精确恢复、临时服务停止；main 推送后 Pages / 普通公开源字节与首页 / 指引卡检查闭环。

## 实现验收补充

旧银行实机证明 v70–v81 的容器也仅在当前房间呈现，现已沿各章原 SCENE_FOR / residue 表定位原按钮。实际场景表与 markup 祖先检查找到 v73 闭目梦检员和 v74 梦型审查员错置在门外：两组原节点移回闭目档案室，原处理函数 / 门禁 / 存档不变，原出口留在回执容器之外。规范 pending 会由原章在抵达、源重放或别处取消时改变；指引读取这一处理后的状态，不改变原取消语义。

32,566 全站断言、65/65 旧章、桌面 / 375px 代表路线与恢复通过；详见 [v124-browser-qa.md](../design-qa-evidence/v124-browser-qa.md)。
