# 没有地址的春信 / A LETTER WITHOUT AN ADDRESS

2026-10-25，Codex 设计，承接已发布的 v128「余温温室」。Gemini 3.8 Flash High 负责生产前端与实施文档，Codex 负责设计、原画和独立验收。本文记录 v129 开发前冻结的合同；当前发布状态见 [ProgressLog](../../docs/ProgressLog.md)。开发起点的线上基线为 `711c9c8`（功能 `c86c7ad`）。

## 回到那间邮局

旧投递所最后说：「最后收件人：你。」温室之后，邮局第一次收到无需退回的东西。不是神的回信，只是你曾经给某个地方留下过春天，那个地方如今也有话想说。

从无主投递所原登记台之后进入一间新增的「春信摊平室」，场景 `unaddressed-spring-letter`。原投递三封退件、签收空白件、三个后室入口及全部文案保持原样。新增房间预计使全站达到 282 场景。

本章让玩家选择信的来处、亲手沿墨线走完一条投递路线，再决定信寄给谁。完成任意一封即可推进清晨指引；三封 × 三种寄法共九份余韵均为可选回访，不以集齐为通关条件。

## 三封来信

可取信件只读 v128 的规范 `outcomes`。窗台 / 抽屉 / 空椅各解锁一封，可随时再次取同一封，不要求重做温室。没有解锁的信夹显示具体原因与返回温室的普通链接。一次只照看一封，进入不自动创建草稿；有草稿时不能换来处，完成送出后回空台再选。

| ID | 名称 | 开场与信中文字 |
| --- | --- | --- |
| window | 风没有写门牌 | 窗台的叶子替你截住了一封信。信封里没有邮票，只有一阵折好了的风。／「如果你还记得那盏灯，请把它留给下一位晚归的人。」 |
| drawer | 灰里留着一句话 | 那只抽屉终于肯打开了。纸的边缘烧缺了一角，缺口长出一条很细的绿线。／「没有说完的事，可以先放在这里。明天也算一种回答。」 |
| chair | 空椅借出一个位置 | 椅脚边压着一封平平整整的信。它没有署名，却给收件人留了足够的空白。／「不必坐满每一把椅子。有人经过时，能歇一会儿就好。」 |

来处在取信时捕获；温室后来增加其他结果不能更换手中来信。不读取祷词、不推断旧愿望原文，也不虚构温室没有保存的历史判词。

## 玩法：一笔信路

纸上有十二个墨点，按三行四列排列，读屏编号 1–12，内部编号 0–11。墨点可重复经过，每条相连墨线只能走一次。自动从「起笔」开始，用原生按钮逐点选择；所有墨线都走完且停在「信口」，才能封信。没有计时、扣分、操作上限或失败惩罚。

三张图分别有 12 / 13 / 14 条线，难度逐步增加。墨点间只允许上下左右邻接，无对角线、无首尾穿越。过早走向信口可能把未走的环留在身后，页面明确显示尚余墨线，支持撤回与从头描。

只给当前可走的点视觉强调；所有点仍是清晰的原生按钮，非可走点点击只反馈原因、不保存。每条线同时用颜色与实线 / 虚线、已走标识区分，不能只靠颜色。笔尖位置、走过的编号序列、已走线数、可走点以及起终点有文字呈现。SVG 只画线，`aria-hidden`，交互不依赖 SVG、拖拽或坐标命中。

「借一阵风指路」只指出下一点。若当前路线已无法完成，计算最少需撤回的步数，提示「先撤回 N 步，再走到第 X 点」；玩家仍自己操作，提示不写存档。撤回一步只移除最后一点；重置保留来信种类。封信冻结路线，拆开可继续编辑；封好不等于投递完成。

## 三种寄法与九份回响

封好后出现三张去向卡，均能选择，与来信种类自由组合。`tomorrow` → threshold；`stranger` → deadletter；`unsent` → remembrance。真实抵达才记账，落点展示对应固定余韵及回摊平室的普通链接。

| 寄法 | 按钮与结局标题 | window | drawer | chair |
| --- | --- | --- | --- | --- |
| tomorrow | 寄给明天的自己／你也可以成为等信的人 | 门缝下多了一道浅绿的折痕。明天开门时，你会知道有人替你把灯留着。 | 门外还没有脚步。你把那句没说完的话放在门槛上，给明天留了位置。 | 门前摆着一把小椅子。它不催你出发，只让明天回来的人有地方歇脚。 |
| stranger | 留给下一位路过的人／收件人不必先有名字 | 投递所第一次把一封信放进了「可领取」的格子。经过的人能从纸里听到风。 | 灰纸被放进一格空柜。有人终于可以收下一个问题，而不必替它作答。 | 格柜里腾出一个空位。信上只写着：如果你累了，这里还坐得下。 |
| unsent | 今天先不寄／没有寄出，也不是退件 | 痕迹墙留住了那阵风。你可以等到想起某个人时，再给它一个方向。 | 那句未完的话安静地留在墙边。它没有被烧掉，也不必今天就成为答案。 | 墙边多了一把画在纸上的椅子。暂时没人坐下，位置仍然算数。 |

「今天先不寄」是完成的选择，不能标为失败、欠账或阻止后续章节。已完成的余韵只读保存，不能反复提交同一草稿。再次取同一来信可体验不同寄法，计数可递增而余韵去重。

## 页面与原画

独立原画 `assets/v129-unaddressed-spring-letter.webp`：旧邮局侧面的小桌，三只浅信夹、一张摊开的空白厚纸，细绿叶脉从左侧信纸伸展，少量灰烬、空椅影，背后是暗铜气送管和格柜；冷清晨光，灰绿与旧铜，延续前作。图里没有字、数字、UI 或可点击棋盘。

原画在上，操作台在下。桌面最大宽度约 1080px，宽屏故事旁注 + 信路两栏；375px 单栏，棋盘宽度跟随可用空间，4 列墨点按钮各至少 48×48px。信路在平面可读区域呈现，不盖在透视原画上。灰白纸色、深墨文字、暗绿走线、旧铜强调，保持本站黑色背景；正文对比至少 4.5:1，状态与焦点不只靠颜色。

所有新 ID / CSS 以 `sl-` 开头（场景和目录 ID 除外）；`[hidden]` 真隐藏，`focus-visible` 明确，reduced-motion 停装饰动效。三个抵达标题和新房标题预留固定治理栏的 scroll-margin，聚焦仍走宿主的 pendingSceneFocus，目录打开时不抢焦点。

## 状态与宿主约束

仅写新键 `goddead_v129_spring_letter`，version 129。生产独立文件 `spring-letter-rules.js`、`spring-letter.js`、`spring-letter.css`。不改 `warmth-*` / ink / light / tea / directory 的实现。

顶层恰七字段：`version,visited,outcomes,letterCount,lastLetter,draft,pending`。默认 129 / false / [] / 0 / null / null / null。

- `outcomes` 为 `window:tomorrow` 等九种 ID 去重，按来处 window,drawer,chair，再按寄法 tomorrow,stranger,unsent 排序。
- `letterCount` 是 0–9999 整数，不能小于已收集余韵数；0 时 outcomes 空且 lastLetter=null，大于 0 时 lastLetter 恰 `{letter,recipient}` 且对应余韵存在。
- `draft` 恰 `{letter,path,sealed}`，由纯规则验证，不保存信件原文、任意路由、HTML、解答缓存或时间戳。规范读取不执行 getter、不隐式类型转换；未知字段拒绝。坏 draft 丢弃，同时取消依赖它的 deliver pending；合法历史不丢。坏顶层基础历史回到本章默认。
- enter pending 恰 `{kind:'enter',source:'deadletter',target:'unaddressed-spring-letter'}`，抵达才记录 visited。
- deliver pending 恰 `{kind:'deliver',source:'unaddressed-spring-letter',target,letter,recipient}`；目标严格由寄法推导，必须真实 visited、sealed 且路线完整，letter 与 draft 一致。
- 完成只在真实合法目标抵达时原子更新 outcomes / letterCount / lastLetter，并清 draft / pending。来源刷新重播，目标刷新不重复计数；第三场景取消 pending，保留封好的信。没有自动取下一封。
- 合法资格为 `remainingWarmthUnlocked() && getRemainingWarmth().plantCount > 0`。临时资格不足只藏入口、禁止操作，不抹合法草稿 / 历史。深链新房须资格完整且 visited 或合法 enter，否则返回 remembrance。
- 上游忙态包括原清晨名重上游、名重 pending / 活动 confession，以及温室 pending / 活动 draft；忙态暂停，不能成为清档理由。
- 旧投递所首锁：旧动作已经占用 AutoAdvance 时新入口不写新状态；新 enter 占用 deadletter 后，以独立 capture 闸门及自有 inert / aria 标记暂锁旧房旧业务 button，源刷新恢复，抵达 / 改道 / 遗忘释放。保留旧 disabled 和其他来源的 inert / aria 状态。普通出口链接及只导航的 `button[data-go]` 不锁：实际旧出口「回到交换台」正是这种按钮，允许主动改道。禁止改全局 AutoAdvance 为 first-wins。
- UI 业务动作要求 trusted 原生输入、正确场景、完整资格、非忙、无本章 pending、无旧来源 AutoAdvance、控件可用；sync 不创建记录、结算或导航。
- 痕迹页增加新入口、继续手中信、九份可选余韵。清晨指引在温室至少一盆、没有温室活动事务时转交本章。原目录 279 项字节保持，仅加 `32ε / 没有地址的春信`，真实到访才显示。outstanding 继续只读，旧回执优先。

## 独立规则 API

冻结命名空间 `GoddeadSpringLetterRules.create()`，冻结实例恰十方法，不接收 DOM、存储或宿主。

| 方法 | 契约 |
| --- | --- |
| layout(letter) | 返回全新 `{letter,rows:3,cols:4,start,end,edges}`；非法 letter 返回 null |
| createDraft(letter) | 返回全新 `{letter,path:[start],sealed:false}`；非法返回 null |
| normalizeDraft(raw) | 纯对象 / null 原型、恰三字段、dense 普通数组 path；0–11 整数，不重复边、不跳边、不越界、起点正确、长度不超边数+1；sealed=true 必须完整；有效返回规范新对象，非法返回 null |
| analyze(draft) | 返回 `{current,used,total,complete,stuck,available,visitedEdges}`；available 是按编号升序的未走相邻点，sealed 时为空；visitedEdges 按行走顺序返回图内边索引；stuck 为未完整且没有可走点；非法返回 null |
| options(draft) | 返回 analyze.available 的新数组，非法返回 null |
| step(draft,node) | 合法可走整数点才返回追加路径的新草稿；sealed、非法点、已走边、越界均返回 null，不改变输入 |
| undo(draft) | 非 sealed 且有一步可撤则返回新草稿，否则返回合法输入的新副本；非法返回 null |
| reset(draft) | 非 sealed 重置同类初局；sealed 返回新副本；非法返回 null |
| seal(draft,value) | value 必须布尔；true 仅完整路径可封，false 可拆开；非法操作返回 null |
| hint(draft) | 返回 `{next,undo}`；完整含 sealed 返回 `{next:null,undo:0}`；对未完整路线，找最少撤回后可完成的前缀，返回该前缀字典序最小完整续路的第一点，undo 是最少撤回步数；提示不修改草稿；非法返回 null |

所有输出与调用之间独立，无输入别名。拒绝稀疏、extra-own-key、symbol、accessor、定制原型数组 / 对象，处理非法输入不抛异常；不承诺防御恶意 Proxy。
