# 余温温室：概念验证

日期：2026-10-18 起（Asia/Taipei）。本文件按日期保留 Codex 设计与独立 QA 历史，不属于 v127 分茶铺验收。最新状态见末节：2026-10-25 已完成真实页面本地试玩；公开发布另记。

## 九格规则

使用行优先九位状态；单阀翻转自身与曼哈顿距离为 1 的有效邻格。目标为九位全暖。根代理以独立 Node 位运算枚举，另一个只读设计审查代理分别用状态图与 GF(2) 线性代数复核，两侧结果一致。

| 检查 | 结果 |
| --- | --- |
| 九阀变换矩阵秩 | 9 |
| 512 种操作奇偶组合 | 得到 512 个不同状态差量，无重复 |
| 从全暖反向 BFS | 512 个状态全部可达，检查 4,608 条有向边 |
| 最短距离 0–9 的状态数 | 1、9、36、84、126、126、84、36、9、1 |
| 同阀两次复原 | 512 × 9 种检查通过 |
| 非终态提示 | 511 个状态中，选择解中一阀后距离都减少 1 |
| 状态与奇偶解交叉穷举 | 262,144 个组合，每状态恰有一个奇偶解 |

三个候选初局分别为 `011/101/110`、`101/010/101`、`000/000/000`，最少步数为 3、4、5，对应阀集合 `{1,5,9}`、`{2,4,6,8}`、`{1,3,5,7,9}`。同一集合内阀的顺序任意，最短操作序列分别有 6、24、120 种，不是唯一操作顺序。任意状态最多九步可解。

## 已核对的旧接口

核对工作区 `script.js` 的规范治理读取、主线 `resolveScene`、清晨验名的资格 / 等待 / 草稿，以及原 `offerPrayer()` 行为。真实接口及冻结门禁写入 [Design.md](Design.md)。旧焚献前置与清晨完成是两个条件，不能仅凭清晨完成就开放焚献室。原祷词仅参与旧焚烧流程；新章不得读取该输入或将私人原文送入外部模型。

新房间候选名 `remaining-warmth-garden` 以及前缀 `RW_ / rw- / remainingWarmth` 在当前 JS / MJS / HTML / CSS 中未见冲突；未占用版本号或新键。前端实现前仍需再检索一次。

## 审查推动的修订

- 将“预览五格”改为角 3 / 边 4 / 中 5，避免边缘提示虚构邻格。
- 将“完成都回焚献室”改为按放置选择进入三个实际目标；提盆与放盆动作本身不计完成。
- 将模糊的 64 步历史改为 `baseParity + moves` 检查点，避免截断历史导致刷新丢进度。当前格子与完成状态都由历史推导。
- 新盆捕获规范旧裁决；当前盆不被后来的旧裁决改动重抽。原章节键保持只读。
- 抵达记账同时消费活动盆、清除提起与在途状态；只读的上一盆记录不能再次提交，避免回温室后反复交同一盆刷次数。
- 区分 `draft === null` 的无活动盆与 `draft.capturedRuling === null` 的合法白芽案；不得使用裁决真值判断资格。
- 画廊若需新桥，只开放合法放置事务或已完成空椅记录对应的画廊，且完整旧资格仍成立。
- 原画与操作面板分开，九格不在透视石床上做错位热点。
- 实际集成检查发现旧 `AutoAdvance.schedule` 会覆盖同场景计时器；新入口和旧焚献判词必须双向首锁。在本章焚献室来源事务在途时，旧判词 / 继续 / 焚献点击与 Enter 都局部拒绝，不读取或清空私人输入；取消后恢复旧可用条件。需实测两种点击先后与旧存档不变。
