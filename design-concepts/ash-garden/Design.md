## 为什么回到这里

原焚献室让一句非空祷词变成灰。清晨回访已经照亮回声、血管和忏悔，现在让焚献室也发生一次温柔而不完全可靠的变化：炉火已经熄灭，抽屉里却冒出一片叶子。它没有把神叫回来，只把烧过的愿望留成了可以照看的东西。

保留原祷词输入、焚献动画、甲乙治理裁决、因果疤痕、旧签收人及出口。新玩法不要求再写一句私人祷词，不读取或展示玩家曾输入的原文，更不将原文交给生成模型。新场景只使用预写的虚构愿望。

## 入口与节奏

建议在完成 v121 任一清晨验名回访后，从痕迹页再次指向旧焚献室；旧上游仍须真实解锁。若清晨链有未交回的回执或草稿，先接完旧事。入口是炉底抽屉冒出的叶尖，不修改旧炉图和原按钮的点击区域。

新增一间独立温室作为主要操作场景，完成后回到所选的旧场景留下变化。不是再开三个部门、九种订单和一次必须集满的听证：照看一盆就可完成，其余去向属于自愿回访。

2026-10-18 已核对当前代码，冻结入口边界如下：

- 清晨资格是 `morningNameUnlocked() && getMorningName().reconciled.length > 0`；同时要求旧焚献主线的完整前置 `watchUnlocked() && line4Unlocked() && getLine4().connected && getDL().accepted && getCancel().refused && getActing().appointed`。旧支线通行桥或曾到访标记不能单独开启温室。
- 旧链等待条件是 `mnUpstreamBusy() || st.pending || st.draft.confession`，其中 `st = getMorningName()`。有旧待签收或未交回草稿时，新入口给出返回旧事的提示；不清除旧事务。
- 持久解锁资格与临时忙碌分开：旧上游忙碌时暂停新操作与新转场，保留活动盆和可恢复记录；规范读取不能因为暂时忙碌就抹掉新章进度。
- 新盆开始时只读 `parseAndValidateGovernance().rulings.offering`，捕获规范值 `A / B / null`。本盆进行中旧裁决变化不重抽开局，重来仍保留本盆案例；明确选择照看新盆后才重新捕获。
- 全章只新增独立存档键，不写旧裁决、祷词、v121 或其他章节键。新房间为 `remaining-warmth-garden`；2026-10-23 开发切片冻结 `goddead_v128_remaining_warmth` / version 128 与 `rw-` UI 前缀，详见 FrontendContract.md。
- 痕迹页下一步只在完整入口资格成立后接到温室；若只完成清晨、旧焚献前置尚不齐，保留现有清晨完成提示，不放一个点了只能退回的温室入口。一盆完成后即显示本章完成，另外两处去向只作可选回访。

## 核心操作：九格余温

窗边灰床有 3×3 个相连的温格。每格只有“冷 / 暖”两态；拨动一枚铜阀，会翻转它自己及上下左右相邻格，边界不绕回。小芽已经从灰里探头，但根还受着冷；让九格同时温暖，才能安全提起花盆、为它找一个去处。无计时、无生命值损耗，无需声音，也不要求拖拽。

- 每格为原生按钮，读出行列、冷热和受影响的相邻格；形状与文字同时区分冷热，不能只靠红绿色。
- 操作前预览本格与有效相邻格的影响范围：角落 3 格、边中 4 格、中心 5 格；键盘聚焦和指针悬停均可预览，触屏第一次点击仍直接操作。操作后给出具体变化，错误可以立即撤回。
- 保存本案类型、压缩过往操作的奇偶位图与至多 64 次近期操作；当前温格由它们重放得出，刷新接着做。重来只重置本案，不清空其他章节。
- 可选“听一片叶子的提示”：只提示当前解中下一枚阀，不自动点击；不得以额外剧情惩罚使用提示。
- 同一阀操作两次复原。候选初局由已知解反推，独立穷举验证，不能用任意随机格碰运气。

旧焚献裁决影响开局及植物叙述，不影响可达性或把某一裁决写成坏结局。以下 `A / B / null` 是只读案例映射，叙述是温室的新意象，不改写旧判词。九格以行优先 1–9 编号；初局字符串中 `1` 为暖、`0` 为冷，斜线分行。

| 旧裁决 / 案件气质 | 初局 | 最少解阀集合 | 已验证最少步数 | 植物意象 |
| --- | --- | --- | --- | --- |
| A / 灰保住了原来的形状 | 011 / 101 / 110 | 1、5、9 | 3 | 叶脉像未展开的信 |
| B / 余响沿根须回到土里 | 101 / 010 / 101 | 2、4、6、8 | 4 | 叶背留着一圈细小的钟纹 |
| null / 没有判词也能活下来 | 000 / 000 / 000 | 1、3、5、7、9 | 5 | 一株没有标签的白芽 |

独立穷举已确认所有 512 种状态可解，每种状态有且只有一组操作奇偶解；操作顺序可以不同，不称“唯一路线”。提示选当前最少解中编号最小的一枚阀，操作后最短距离恰好减一。数学与边界检查见 [DesignQA.md](DesignQA.md)，这不是前端已通过验收的证明。

### 有限历史，完整恢复

每盆持久化 `baseParity`（整数 0–511，九位操作奇偶）与 `moves`（长度 0–64，元素为 0–8 的整数）。由案例初局应用 `baseParity`，再重放 `moves` 得出当前格子；不把存档中的 `board` 或 `solved` 当作事实。第 65 次操作时，把最旧操作的对应位异或进 `baseParity`，保留最近 64 次。撤回只弹出近期操作，到检查点停止并解释“较早的余温已记入灰床”；重来将二者复位为 `0 / []`。

`draft === null` 才表示没有活动盆。活动草稿的 `capturedRuling` 可以是 `A`、`B` 或合法的 `null`；后者正是白芽案，不能用真值判断把它误当空档。

只有推导出九格全暖才允许提盆；提起后锁定温格，仍能放回继续调整。`holding` 必须为布尔值且全暖才可保留，在途时禁止再改盆。规范读取严格检查字段、整数范围和案例白名单；这保证本地状态一致性，不宣称能阻止玩家编辑整份 localStorage。

## 三种去向，不排高下

九格全暖后，不弹出结算法庭，而是实际提起花盆；三个可见物件决定把它放在哪里。抵达才确认一次完成，源场景刷新重放，目标刷新不重复结算；未选择前仍能放回灰床。

三去向固定映射为窗台 → `threshold`、抽屉 → `offering`、空椅 → `unending-gallery`。目标必须从合法放置类型推导，不能采用存档里的任意路由。全暖、提起、放回均不结算；只有从温室出发的合法放置事务真正抵达对应场景才记录一次结果并清理在途状态。离路取消只取消事务，保留本盆操作供续接。

抵达成功必须在同一次章节规范写入中完成：加入对应余韵、累计次数、更新上一盆只读记录，并清空活动本盆、`holding` 与 `pending`。回温室只能观看上一盆，不能把已经交出的全暖盆再次交付；只有明确选择“照看新盆”才创建新的案例与初局。上一盆记录不携带可继续提交的草稿。

焚献室沿用原主线门禁，不新增通行绕道。画廊只增一条严格限定于本章的窄桥：入口资格仍完整成立，且存在目标为画廊的合法放置事务，或已有本章空椅落盆记录；它只允许画廊，不扩张其他旧房间的权限。源刷新可重放、目标刷新不重复记账、同帧双击只生成一笔事务，均须用实际浏览器再次验证。

### 与旧焚献动作的局部互斥

当前 `AutoAdvance.schedule` 会先清除同场景原计时器；旧 `applyRulingOfferingChoice`、`scheduleOfferingAutoAdvance` 没有首锁保护。因此只让温室入口检查 `AutoAdvance.has('offering')` 还不够：新入口先触发、随后点旧判词，仍会被旧转场覆盖。

冻结为双向首锁：旧焚献已有转场时，新入口不抢占；本章合法 `enter` 事务的 `source === 'offering'` 在途时，旧甲乙判词、旧继续按钮以及焚献按钮 / 输入框 Enter 都暂时不可触发。UI 与事件入口都要防护，不能只变灰按钮。优先采用本章独立 capture 事件闸门，在调用原处理函数之前拦截；旧函数正文保持原字节。防护发生在读取祷词和修改旧存档之前；保留输入框原文，不清空、不捕获或转存。事务抵达 / 取消后恢复旧控件原有可用条件，不能无条件打开其他旧锁。普通出口和目录仍可使用，以允许离路取消。只在本章实际占用焚献室的短暂时段生效，不改全局调度器、旧判词内容、正常旧流程或跨房间权限。

| 放置位置 | 余韵 | 旧世界的可见回声 |
| --- | --- | --- |
| 面向门外的窗台 | 「有一阵风认出了你」 | 门外多一片在风里发亮的叶影；不改变敲门次数 |
| 原来的灰烬抽屉 | 「没有被回答，也没有被烧尽」 | 焚献室抽屉留下根须；原炉与祷词流程照常 |
| 那张一直空着的椅子 | 「缺席也有了需要浇水的东西」 | 无终局画廊空椅脚边有一盆植物；不复活神、不覆盖其他结局 |

一次完成即可退出；三种可选余韵分别记忆，不强迫重复全部九格。再次回访可照看新盆，也可只看上一盆，不自动启动谜题。

## 叙事稿与交互语气

开场：「炉火早就熄了。你拉开盛灰的抽屉，里面却有一小块地方还暖着。不是神的手。也许只是某个愿望，终于学会了不等回答。」

灰床上的三句无署名刻字是固定的虚构文本，与玩家旧祷词无关：甲案「愿离开之后，还会有人替我把灯关上。」；乙案「愿最后一句话，能找到一双不用回答的耳朵。」；无判词案「愿没有写下来的事，也能有一个春天。」

每格显示编号与「冷 / 暖」，当前提示写成「第 2 行第 1 格的阀，会改变这四处余温」一类准确叙述；不评价玩家聪明或失败。提示按钮叫「听一片叶子的提示」，重来叫「让余温回到最初」，提盆叫「把这盆小芽提起来」。全暖时：「根底已经暖了。它不需要你证明什么，只等你选个地方。」

窗台余韵：「门外依然没有人。叶影却先你一步走了出去。」抽屉余韵：「你没有再添火。根须绕过那些灰，像绕过一句不必补写的回答。」空椅余韵：「椅子还是空的。只是从今天起，你路过这里时，多了一件可以做的小事。」

## 视觉方向与资产

黑灰石墙、磨旧铜管和原焚献炉延续既有房间材质；天光第一次带一点灰绿，不能变成明亮农场 UI。植物应小得需要照看，不是覆盖整个世界的魔法森林。

首张原画已保存为 [ash-garden-room-v1.png](ash-garden-room-v1.png)：炉旁一座狭窄的旧温室，窗台、石灰床与空椅构成三处叙事落点。图片不烘焙文字、按钮、九格状态和数字；实际九格必须由前端原生控件渲染。原画只建立空间，不能拿截图样机当已实现页面。

石灰床有透视，九格控件应在独立面板排布，不把等距按钮硬铺在斜透视画面上。窗台、抽屉和空椅的文字出口也使用清晰的原生按钮，艺术画面负责空间，不承担唯一点击提示。

完整生成提示词、尺寸、哈希与视觉检查见 [ImagePrompt.md](ImagePrompt.md)。首张 1536×1024 原图已通过物件、亮度与布局概念检查；真实页面可读性仍须前端合成后检验。

网页候选副本 [ash-garden-room-v1.webp](ash-garden-room-v1.webp) 保持原尺寸与构图，为 317,952 bytes；PNG 原件保留。两者均不属于 v127 生产资源。
