# 余温温室：真实页面接入清单

2026-10-18，Codex 依据 v127 工作区冻结的设计 / 源码接入合同。2026-10-25 验收附记：Gemini 已按下列边界接入实际页面，独立源码与单标签浏览器验收通过，证据见 [v128-browser-qa.md](../../design-qa-evidence/v128-browser-qa.md)；公开发布另记。主设计见 [Design.md](Design.md)，以下保留最初接入约定。

## 生命周期

- `sceneInit`：在 `replayMorningNamePending(name);` 之后、痕迹页指引刷新之前处理本章。依据实际 `name` 进行目标抵达记账 / 第三场景取消，随后同步 UI 和合法源场景重播。第三场景取消只撤在途，不丢本盆。
- `resolveScene`：旧清晨验名桌守卫之后加入温室独立深链守卫。需要完整资格及本章真实到访或合法 enter；忙碌只禁止操作，不删除草稿。offering 旧守卫不动；画廊仅追加本章 gallery-only 窄桥。
- 抵达聚焦：在 `focusMorningNameArrival(name);` 附近接入本章余韵标题，源操作 / 提示不擅自把焦点扔到别处；旧门环和祷词输入仍保留原路径。
- 全部遗忘：在 `forgetMorningNameState();` 与 `forgetCodexFolds();` 之间接本章清理。只清本章键、计时、持盆、预览与新增回声，释放本章造成的焚献局部锁；清理不能遗留 pending 或自启动新盆。
- 冷启动：`syncMorningNameAll();` 后仅同步本章 UI。实际 `route()` 前不能对硬编码 threshold 提前结算或取消一个合法草稿 / 事务。
- 痕迹指引：`morningNameProgressStep` 已完成分支在完整温室资格成立时才交给新章；优先旧等待，然后新在途 / 活动盆，再一盆完成。outstanding 清单接在 v121 后，保持只读和旧回执优先。

## HTML / CSS / 资源

- 焚献室入口放在 `aria-label="离开焚献"` 导航前的独立面板，不能塞进旧 `role="img"` 的炉图或覆盖旧点击区。
- 痕迹页增加本章入口、记忆与可选余韵；新增温室 section 与现有 `scene-morning-name-balance` 并列。
- 目录静态加入候选 `32δ / 余温温室` 链接，仅真实到访后显示。现有目录引擎可自动归入“清晨回访”，无需改写引擎；动态迟插链接会错过 attach，不采用。
- 原画保留 `data-src` 懒加载、固定宽高与描述性 alt。九格与三出口为独立原生按钮，不依赖画面热点。
- 样式局限 `rw-` 命名空间，明确处理 `[hidden]`、44px 控件、375px 无横溢、focus-visible 与 reduced-motion。
- 纯规则如独立文件，必须在主脚本之前阻塞加载；版本号与最终资源路径在实装边界确定时统一，不在概念阶段提前改缓存。

## 焚献首锁专项

`AutoAdvance.schedule` 先清同场景旧 timer；旧判词与继续动作会排往 reliquary。原祷词本身不排路由，但会修改次数并排标题聚焦。采用局部 capture 闸门＋禁用展示，仅在本章合法 enter pending 确实占用 offering 时拦截：

- `#prayer-offer` 点击与 `#prayer-input` Enter；
- `#ruling-offering-btn-a`、`#ruling-offering-btn-b`；
- `#continue-offering-btn`。

拦截在读取输入原文、写旧存档或调用旧处理函数之前完成。源刷新恢复同一锁；抵达、离路取消或全部遗忘释放本章锁，但不解除其他来源的禁用。普通出口、目录与返回可用。旧先新后、新先旧后、同帧双击、Enter、源刷新和离路恢复都要实测；禁止把全局调度器改成 first-wins。

## 旧测试接线与新增验收

- v121 测试当前提取边界一直到“痕迹室下一步”。插入新模块后应收紧旧模块提取终点，不能让新代码被不完整旧桩吞入。
- site 的相邻生命周期检查、v123 的原 278 条目录链接、v124 的场景数，以及 v125–v127 完整脚本顺序应反映合法新增；原 278 链接仍逐字保留，不能通过删除旧断言来过测试。
- 新章须覆盖三初局与三去向、64 步检查点、提示、冷热与持盆、刷新、双击、源重播、目标幂等、离路恢复、旧忙态和锁定深链。抵达成功同时消费活动盆；回温室不能再交上一盆。
- 完整旧焚献流程仍可用，祷词原文不参与新状态或外部请求。Computer Use 始终只使用一张 QA 标签页，并备份 / 恢复玩家原始存档。
