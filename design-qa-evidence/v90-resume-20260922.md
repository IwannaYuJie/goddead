## 2. 已确认的缺陷与修复边界

### 冷启动错误抵达

生产 bootstrap 曾在真实 route 前调用 `resolveCauselessConsequencePendingOnArrival("threshold")` 及 replay，导致非 threshold 的 source/target pending 被清除，或 threshold 目标提前结算。独立实际模块复现 entry/refugee/asylum 丢失。

Gemini 3.7 Flash High 已移除两次硬编码调用，保留九项 UI 同步；实际 route→sceneInit 负责结算与续播。同时恢复 source reload 的规范 feedback。代码和新回归测试均由 Gemini 编写、机械应用。

生命周期自动测试已通过16725断言；新回归执行源文件抽取的 bootstrap、AutoAdvance、goScene、route 和 v90场景抵达链，覆盖7种 pending 的13个代表fixture、source/target/else、重复hash与幂等。故意把旧错误重新注入内存以及移除feedback时，测试均失败。该测试隔离了上游gate，不能证明完整解锁链性能。

### 后期解锁链重复遍历

v81–v90 gate 同时显式调用前章 gate、再调用内部已经检查该gate的前章getter，导致每层重复。真实 v82–v90 模块的完整夹具检查得到 U90→U81 调用数1、2、4、8…512。v81–v90 单次U90会调用基线v80 gate1024次。

独立内存实验仅移除十个可证明冗余分支后，相同true结果只调用基线gate一次；100次U90从约273.29ms降至6.04ms（廉价stub基线，仅为复杂度证据，不是浏览器帧率或生产基准）。v67–v70的显式gate不能一并移除，因为旧getter在锁定时仍可能返回历史records。

完整上游种子的浏览器卡住现象与此结构相符；修复后仍需重跑浏览器才能确认产品恢复。
