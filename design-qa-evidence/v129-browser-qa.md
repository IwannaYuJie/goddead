## 真实浏览器范围

全程使用一个 Chrome Computer Use 标签（本地 `127.0.0.1:8894`），通过原生鼠标、Enter、Space 和滚动操作。桌面宽 1470px，窗口高度曾为 744px / 688px；窄屏为同一桌面浏览器的 375×812 视口模拟，并非实体手机。上游使用本地测试进度，未重玩整条历史章节链。新章从无存档开始，未用脚本代替描线或结算。

- 走完窗台来信 → 明天的自己、灰纸来信 → 下一位路过的人、空椅来信 → 今天先不寄。第三条是有效完成选择。再次描完窗台来信寄给自己后，累计 4 封、仍为 3 份独立余韵。原生覆盖三组代表组合和一次重复；九组合由独立运行时测试覆盖。
- 首次进入源房刷新，正确抵达空台并清 pending。非法墨点与指路不改变 raw；走入窗台断路后提示最少撤回 6 步，再到第 5 点。原生 Enter / Space 撤回、重置、封信 / 拆信正常；未选择去向时不记完成。
- 双击寄信并在源房刷新，只在目标抵达记一次；目标刷新 raw 不变，历史回响不重新抢焦点。灰纸送信途中改道痕迹室，只取消 pending，封好草稿保留；原生继续后可送达投递所。
- 旧空白件先签收，春信入口让路，原注销科落点保持，新章 raw 不变。新入口先行时旧业务按钮 inert，native disabled 未被改写；原 `button[data-go]`“回到交换台”可主动离开，取消入口事务并恢复原属性。
- 温室草稿忙态隐藏信夹与操作台，没有可访问墨点，草稿 raw 保留。隐藏按钮的 native disabled 标志不作为可用性的单独依据。完整资格暂缺时深链回痕迹室，入口和目录隐藏，合法春信 raw 不清；资格恢复可继续。
- 只有窗台安放记录时，仅窗台来信可选，另两项说明缺少的安放条件。打开图鉴可读三份已收集余韵，未收集项保留；章内 raw 不变。图鉴开合会正常写既有折叠偏好。

三个代表路径前后对比 69 项旧 raw 无变化；本地原来的 1 项 raw 在收尾精确还原，新章键不存在，视口复原。控制台记录为 0 warn / 0 error。原始 31 条测量见 [v129-native-cases.json](v129-native-cases.json)。
